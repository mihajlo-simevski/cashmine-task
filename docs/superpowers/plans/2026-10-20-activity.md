# Activity history — design + plan

Time box: 15 min build, deployed by 20:30 UTC. Cut if it slips; nothing else depends on it.

## Design

- **What:** a paginated, newest-first list of accruals, reversals and claims (brief item 4).
- **API:** `GET /v1/activity?limit=20&cursor=…` → `{ items, nextCursor }`; `nextCursor: null` on the
  last page. Item: `id, type (accrual|reversal|claim), asset, amount (signed decimal string), status,
  exchange|null, createdAt, relatedId|null`.
- **Screen `/activity`** (link "Activity" in the Home header, Back button):
  - Row: type label + icon tint (accrual green "+", reversal red "−", claim neutral), asset,
    signed amount (exact, shortened with the `Amount` "more" chip), status badge
    (pending / confirmed / completed / failed), exchange name (plain text), date + time.
  - A claim row with `relatedId` links to `/claims/[id]`.
  - "Load more" button while `nextCursor` exists (no infinite scroll: simpler, works on web).
  - States: skeleton rows, empty ("No activity yet"), error + retry (401 → Change token), and an
    inline error under the list if a later page fails (earlier pages stay).
- **Money:** signed amounts parsed with a new `parseSignedAmount` (sign + the strict parser) to
  `bigint`; never `Number()`. Each item's decimals come from the balances snapshot for that asset
  (the activity item has none); unknown asset → show the API string as-is.
- **Untrusted data:** exchange, type and status render as plain text; unknown type/status values
  are shown as their raw text, never crash (schema uses `z.string()` for them, strict for amounts
  and timestamps).

## Plan

1. `src/features/money/amount.ts`: `parseSignedAmount(input, decimals): ParseResult` (optional
   leading `-`, then `parseAmount`). Tests: `"-0.5"` → `-5n * 10n**17n`; `"0.5"`; `"--1"`, `"-"`,
   `"+1"` → format.
2. `src/features/api/schemas.ts`: `ActivityItemSchema`, `ActivityPageSchema`
   (`items` max 20, `nextCursor: string | null`, signed amount regex `^-?(0|[1-9]\d*)(\.\d+)?$`).
3. `src/features/activity/components/ActivityScreen.tsx` + `src/app/activity.tsx`:
   `useInfiniteQuery({ queryKey: ["activity", tokenKey(token)], initialPageParam: null,
   getNextPageParam: (p) => p.nextCursor })`; rows as above; i18n strings in `en.ts`.
4. Home header: "Activity" link next to "Change token".
5. `pnpm check`, commit `feat: add paginated activity history`, deploy, browser smoke test
   (first page, Load more, a claim row opens its status).
